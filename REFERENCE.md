# Reference

Everything that goes in and everything that comes out. The narrative version, with
worked examples, is in [README.md](README.md); this is the list.

## Input: command line

`./cli.py <command>` in a source checkout, `kronoterm2mqtt_app <command>` inside the
container. Every command takes `-v` (repeat for more) to raise the log level. The full
generated help for both CLIs is in [README.md](README.md#bootstrap-kronoterm2mqtt) and is
regenerated by the test suite, so it cannot drift from the code.

| Command | Does |
|---|---|
| `publish-loop` | reads registers and publishes them until stopped; the normal mode |
| `health` | prints the state of a running loop; exits 0 healthy, 1 unhealthy, 2 endpoint disabled |
| `print-values` | reads every definition once and prints the converted values |
| `print-registers` | reads raw registers from 2000 upward until five errors in a row |
| `print-settings` | prints the settings with credentials anonymised |
| `edit-settings` | opens the settings file, creating a default one first |
| `test-mqtt-connection` | connects to the broker and disconnects again |
| `probe-usb-ports` | tries `/dev/ttyUSB0..9` and prints what answers |
| `systemd-setup`, `systemd-status`, `systemd-stop`, `systemd-remove`, `systemd-debug` | manage the systemd unit (need root) |
| `version` | prints the version |

## Input: settings file

`~/.config/kronoterm2mqtt/kronoterm2mqtt.toml`, or
`/home/nonroot/.config/kronoterm2mqtt/kronoterm2mqtt.toml` in the container. Every value
below is the default; a missing section is filled in from these.

### `[mqtt]`

| Key | Default | Meaning |
|---|---|---|
| `host` | `mqtt.your-server.tld` | broker host name |
| `port` | `1883` | broker port; use 8883 with TLS |
| `user_name` | `''` | leave empty for an anonymous broker |
| `password` | `''` | |
| `main_uid` | `kronoterm` | second prefix in every topic, so two instances do not collide |
| `publish_config_throttle_seconds` | `20` | how often discovery config is republished |
| `publish_throttle_seconds` | `5` | lower bound between state messages |

### `[mqtt_tls]`

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `false` | when false, everything else here is ignored |
| `ca_certs` | `''` | CA that signed the broker certificate; empty uses the system store |
| `certfile`, `keyfile` | `''` | client certificate and key, for mutual TLS |
| `insecure` | `false` | skips hostname verification; for testing only |

### `[heat_pump]`

| Key | Default | Meaning |
|---|---|---|
| `definitions_name` | `kronoterm_ksm` | prefix of the file in `kronoterm2mqtt/definitions/` |
| `device_name` | `Heat Pump` | device name in Home Assistant |
| `model` | `ETERA` | model shown on the device page |
| `port` | `/dev/ttyUSB0` | serial device, or `host:port` for Modbus/TCP (502 if the port is left out) |
| `timeout` | `0.5` | seconds; TCP connections are given at least 3 |
| `pooling_interval` | `10` | seconds between read cycles |

### `[health]`

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | serves the endpoint and runs the watchdog |
| `host` | `127.0.0.1` | inside the container; `0.0.0.0` to publish the port |
| `port` | `8099` | |
| `stale_after_seconds` | `60` | data older than this counts as unhealthy |
| `restart_after_seconds` | `300` | end the process after this much trouble; `0` never |

### `[custom_expander]`

Off by default (`module_enabled = false`). Describes the DIY ETERA expander: its serial
port and speed, the number of thermometers, which sensor index belongs to which loop and
to the solar circuit, relay names and ids, the heating curve coefficient and the solar
pump hysteresis. The fields are documented where they are defined, in
`kronoterm2mqtt/user_settings.py`, because their meaning depends on how the board is
wired.

### `[systemd]`

Written by `systemd-setup`; edit only if the unit lives somewhere unusual.

## Input: Modbus registers

Read as holding registers from device id 20, in blocks computed from the definitions, at
`pooling_interval`. Which registers, and what each means, is data rather than code:
`kronoterm2mqtt/definitions/kronoterm_ksm.toml`, where `register` is the one-based number
from the manufacturer documentation and `scale` converts it to the published value.
Values are read as signed 16-bit.

## Output: MQTT

Home Assistant discovery, so nothing needs configuring on the other side. Topics follow
`homeassistant/<component>/<main_uid>/<main_uid>-<entity>/<config|state|command>`:

```
homeassistant/sensor/kronoterm/kronoterm-dhw_temperature/config      {"name": "DHW temperature", ...}
homeassistant/sensor/kronoterm/kronoterm-dhw_temperature/state       43.5
homeassistant/binary_sensor/kronoterm/kronoterm-defrosting/state     OFF
homeassistant/switch/kronoterm/kronoterm-system_power/state          ON
homeassistant/switch/kronoterm/kronoterm-system_power/command        OFF   <- written by Home Assistant
homeassistant/select/kronoterm/kronoterm-operating_program_selection/state  ECO
homeassistant/number/kronoterm/kronoterm-desired_dhw_temperature/state      47.0
homeassistant/number/kronoterm/kronoterm-desired_dhw_temperature/command    48.5  <- written by Home Assistant
```

`<entity>` is the definition's `name`, lower-cased and slugified. Sensors publish the
scaled number, binary sensors `ON`/`OFF`, enum sensors and selects the mapped string.
Switches, selects and numbers also subscribe to `/command` and write the register that
the value maps to.

Numbers are the registers the manufacturer's Modbus documentation marks RW: the sanitary
water and buffer setpoints, the four heating loops, the pool, the ECO and comfort
offsets, and the system temperature correction. Each carries the range the documentation
gives, and a value outside it is refused before anything is written - the current value
is published again so Home Assistant stops showing the rejected one. Negative settings,
which the offsets are, are written in two's complement, the way the heat pump reports
them.

## Output: health endpoint

`GET http://<health.host>:<health.port>/health` - **200** when healthy, **503** when not,
**404** on any other path.

```json
{
  "healthy": true,
  "uptime_seconds": 3612.4,
  "mqtt": {"connected": true, "host": "mqtt.example.com", "last_publish_seconds_ago": 3.2},
  "modbus": {"port": "192.168.1.2:502", "last_read_seconds_ago": 3.2,
             "last_read_complete": true, "failed_reads": 2, "last_error": null},
  "sensors_published": 107,
  "stale_after_seconds": 60,
  "problems": []
}
```

`problems` is empty when healthy and otherwise lists what is wrong, in words:
`MQTT client is not connected`, `no Modbus read completed yet`, `last Modbus read was
310.4s ago`, `nothing published yet`, `last publish was 88.1s ago`.

## Output: the container

| | |
|---|---|
| Exit code | 0 on a clean stop, 1 when the loop failed or the watchdog ended it |
| `HEALTHCHECK` | `/app/healthcheck.py`, exits 0 healthy and 1 otherwise, which `docker ps` shows |
| Logs | stdout and stderr; `-v` raises the level, `publish-loop -v` shows Modbus retries |
| SBOM | `/usr/share/kronoterm2mqtt/sbom.cdx.json` (CycloneDX) |
| VEX | `/usr/share/kronoterm2mqtt/vex.openvex.json` (OpenVEX) |
| Labels | `org.opencontainers.image.*`, including `revision` - the commit it was built from |
